# 验证范围与验收方法

本文件区分软件正确性、设备兼容性和医学模型有效性。最终交付的本机实际测试结果由项目测试报告记录；下列硬件或病例验收若没有报告，不能视为已经通过。

| 验证层 | 需要确认 | 不能据此声称 |
|---|---|---|
| 纯软件单元测试 | 输入保护、几何、滑窗覆盖、融合、候选编号、审核门禁和报告 | 临床分割准确或转移诊断有效 |
| 合成端到端 | 文件可读写、网格保持、流程可复现、错误明确 | 合成模型可直接用于真实病例 |
| CPU/MPS/CUDA 一致性 | 同一网络/检查点、输入、精度及补丁设置，输出差异可解释 | 某个设备必然更快或所有算子都可用 |
| 真实病例分割 | 专家轮廓、独立患者，Dice/漏检/假阳性及大小/站位亚组 | 仅凭分割分数判断转移 |
| 转移模型研究 | 逐结/逐站病理配对、患者隔离、未见数据及校准 | 自动获得临床认证或跨癌种通用性能 |

## 基本软件检查

运行项目测试命令并保存日志、Python 和依赖版本。以下行为是核心不变量：

1. 原影像不被写回；错误的输出路径明确失败。
2. 概率和掩膜返回原 CT 的物理网格。对角之外的 affine、不同 spacing、各向异性及小于滑窗的体积均要覆盖。
3. 滑窗覆盖每个输出体素；非整除形状不能漏掉尾部，融合不产生 NaN/Inf。
4. 真实推理不得悄悄使用随机/演示权重；检查点结构、通道和预处理约定不匹配时失败。
5. 连通成分只是候选实例。融合团块和误检可留待人工拆分/剔除，不自动填站位或病理。
6. 未经审核的候选和原始概率图不得直接进入放射组学提取；原 CT 与掩膜几何不一致时明确处理或拒绝。
7. 成功的特征输出携带去标识 scan/node ID、原图/标签指纹和配置哈希，并在研究清单中保留患者映射。提取失败明确报错，不发布冒充成功的特征表，也不把未提取值填 0。

## M5 Max 验收

在原生 arm64 环境显式选择 MPS，保存设备诊断和同步测速 JSON。分别记网络前向与端到端耗时，标明预热、重复次数、滑窗尺寸、批量、精度和回退环境变量。CPU 与 MPS 对照必须使用同一检查点及输入；阈值附近的微小概率差异还需观察对掩膜的影响。

当前 Windows 环境无法替代这项测试。未经该机器运行报告，不填写 M5 Max 延迟、峰值内存、加速倍数或温度/功耗等数值。

## 放射组学验证

软件成功运行 PyRadiomics 不等于特征已通过 IBSI 检验。用参考对象验证实现与参数，再在本队列做分割重复性及采集协议敏感性检查。只在有真实 HU/几何的 CT 和复核掩膜上报告数值；GPU 分割使用的归一化数组不进入这条计算链。

单元测试可用可控提取器验证审核门禁和清单，但真实集成测试必须调用已安装的 PyRadiomics；缺包而跳过的测试不能记为提取成功。PyRadiomics 3.0.1 的现代 Python/Apple arm64 构建限制需单独报告，详见 [依赖说明](APPLE_SILICON.md)。

## 旧模型等价性

若未来迁移旧 H5：保留旧环境/模型版本与哈希，对同一输入比对预处理后的张量、层输出及最后概率图，再对独立真实标注评价分割。没有完成这些步骤时，结果名称保持“新架构/新检查点”，不称旧模型的无损升级。
